## 96. ادامه معتبر

ادامه پروژه زمانی معتبر است که:

- مسیر درست باشد؛
- شاخه درست باشد؛
- وضعیت Git شناخته شده باشد؛
- مرحله واقعی مشخص باشد؛
- فایل‌های تغییرکرده شناخته شده باشند؛
- تعارض اسناد رفع شده باشد؛
- تصمیم باز حیاتی پنهان نباشد؛
- گام بعدی از Roadmap استخراج شده باشد؛
- فرمان بعدی محدود و قابل ممیزی باشد.

## 97. ادامه نامعتبر

ادامه نامعتبر است اگر:

- از حافظه شروع شود؛
- موفقیت قبلی فرض شود؛
- فایل ناشناخته نادیده گرفته شود؛
- خطا پنهان شود؛
- Stage بعد زودتر آغاز شود؛
- Contract ساخته شود بدون تصویب؛
- آرشیو منبع حقیقت تلقی شود؛
- Commit یا Tag پیش از پذیرش ایجاد شود.

## 98. معیار انتقال به عامل بعدی

عامل بعدی باید بتواند بدون سؤال حدسی مشخص کند:

- اکنون کجا هستیم؛
- چه چیزی بسته شده؛
- چه چیزی باز است؛
- چه فایل‌هایی تغییر کرده‌اند؛
- چه آزمونی آخرین بار اجرا شده؛
- چه ریسکی فعال است؛
- فرمان بعدی چیست؛
- چه کاری نباید انجام شود.

## 99. معیار پذیرش این سند

این سند معتبر است اگر:

- سناریوهای وقفه و تغییر عامل را پوشش دهد؛
- ترتیب مطالعه را ثبت کند؛
- ممیزی Git را ثبت کند؛
- ادامه پس از خطا را پوشش دهد؛
- آرشیو را غیرمرجع بداند؛
- مرحله جاری و بعدی را بیش از واقعیت اعلام نکند؛
- قالب تحویل داشته باشد؛
- شروط توقف داشته باشد؛
- با Runbook، Status، Roadmap و Decisions سازگار باشد.

## 100. اصل نهایی

پروژه باید بتواند پس از هر وقفه، تغییر گفت‌وگو، تغییر توسعه‌دهنده یا شکست فنی از روی مخزن و اسناد ادامه یابد.

اگر ادامه کار به جمله‌ای مانند «قبلاً در گفت‌وگو گفته شد» وابسته باشد، فرایند تحویل و مستندسازی هنوز کامل نیست.

هر ادامه معتبر با مشاهده وضعیت واقعی آغاز می‌شود، با یک تغییر محدود پیش می‌رود و با شاهد قابل بررسی ثبت می‌شود.

# پیوست جاری — ادامه کار با Verification Registry

پس از بازگشت به پروژه، به‌جای حدس‌زدن مجموعه فرمان‌های تاریخی:

1. `PROJECT-STATUS.md` و `ROADMAP.md` خوانده می‌شوند.
2. Stage جاری از `tools/verification/stages.ts` تطبیق داده می‌شود.
3. برای تغییر روزمره `pnpm verify:fast` اجرا می‌شود.
4. برای پایان زیرمرحله `pnpm verify:stage -- --stage <STAGE_ID>` اجرا می‌شود.
5. اختتام فقط از مسیر `stage:close:prepare` و سپس `stage:close:publish` انجام می‌شود.
6. برای ممیزی Foundation/CI یا پذیرش کلان از `pnpm verify:full` استفاده می‌شود.

اگر Stage در Registry وجود ندارد یا Stage-specific evidence gate آن تعریف نشده است، پیاده‌سازی می‌تواند ادامه یابد اما Stage نباید بسته و منتشر شود تا Registry و معیار پذیرش آن تکمیل شوند.
