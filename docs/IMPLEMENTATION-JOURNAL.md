## 2. قواعد ثبت در Journal

برای هر مرحله باید تا حد امکان موارد زیر ثبت شوند:

1. هدف مرحله؛
2. وضعیت پیش از اجرا؛
3. خروجی‌های ایجادشده یا تغییریافته؛
4. تصمیم‌ها و محدودیت‌های مهم؛
5. خطاهای مشاهده‌شده؛
6. اصلاحات انجام‌شده؛
7. آزمون‌های اجراشده؛
8. نتیجه Build و اجرای واقعی؛
9. دامنه فایل‌های تغییرکرده؛
10. Commit و Tag؛
11. نتیجه نهایی و مرحله بعد.

قواعد قطعی:

- فقط نتیجه مشاهده‌شده ثبت می‌شود.
- وجود کد بدون آزمون، «آزموده‌شده» محسوب نمی‌شود.
- وجود طراحی یا Contract، «پیاده‌سازی‌شده» محسوب نمی‌شود.
- موفقیت Build به‌تنهایی به معنی پذیرش مرحله نیست.
- بسته آرشیوی یا گفت‌وگوی قبلی، شاهد اجرای مخزن فعلی نیست.
- خطاها نباید از تاریخچه حذف شوند.
- اگر مرحله هنوز Commit یا Tag ندارد، باید صریحاً ثبت شود.
- زمان فنی در خروجی برنامه‌ها باید UTC و ISO باشد.
- رابط عمومی باید فارسی و راست‌به‌چپ باشد.
- فایل‌های متنی فارسی باید UTF-8 بدون BOM باشند.
