## 8. الزامات قطعی و غیرقابل‌نقض

### زبان و رابط

- تمام متن‌های قابل مشاهده برای کاربر باید فارسی روان باشند.
- نمایش واژه انگلیسی خام در رابط عمومی ممنوع است.
- جهت رابط عمومی راست‌به‌چپ است.
- خطای فنی خام، Stack Trace یا پیام کتابخانه نباید به کاربر نمایش داده شود.
- متن فنی انگلیسی فقط در کد، قرارداد، گزارش فنی و مستندات توسعه مجاز است.

### تاریخ و زمان

- تمام تاریخ‌های ورودی و نمایشی رابط عمومی باید هجری شمسی باشند.
- انتخابگرهای تاریخ باید بر پایه تقویم هجری شمسی باشند.
- زمان ذخیره، انتقال، صف، رخداد فنی و گزارش سیستمی باید UTC و ISO باشد.
- منطقه زمانی کاربر یا سازمان باید هنگام تبدیل نمایش لحاظ شود.
- زمان محلی دستگاه نباید منبع حقیقت باشد.

### معماری و داده

- معماری مصوب: یکپارچه ماژولار با چهار برنامه اجرایی مستقل.
- PostgreSQL منبع نهایی وضعیت پایدار تجاری است.
- Redis منبع نهایی حقیقت تجاری نیست.
- داده‌های سازمانی باید جداسازی سخت‌گیرانه داشته باشند.
- سیاست پیش‌فرض دسترسی، عدم دسترسی است.
- شناسه منبع به‌تنهایی مجوز ایجاد نمی‌کند.
- فایل‌ها به‌صورت پیش‌فرض خصوصی هستند.
- بسته‌های آرشیوی و پروژه‌های نمونه، مرجع الزام‌آور مخزن فعلی نیستند.

### کیفیت و پذیرش

- هیچ مرحله‌ای صرفاً با وجود کد یا Build موفق بسته نمی‌شود.
- آزمون مثبت، آزمون منفی و آزمون یکپارچه مرتبط باید اجرا شوند.
- تغییرات باید با UTF-8 بدون BOM ثبت شوند.
- هیچ موفقیتی بدون مشاهده خروجی واقعی فرض نمی‌شود.
- هر مرحله بسته‌شده باید Commit، Tag، مستندات و فضای کاری پاک داشته باشد.
